## 对应架构的实机验证

在最终设计所依据的实机流程中，曾实际验证以下事项：

- 原官方 Tailscale 连接停止后，当前 Clash 本地代理仍可访问国内外网站；
- Google、GitHub、国内测试站点 HTTP 200；国内直连，国外出口属于服务器；
- SOCKS UDP DNS 查询成功；独立内核冷启动后可重新建立连接；
- 源 YAML 的 `dialer-proxy` 与 GUI 生成配置不一致时，可复现依赖原 Tailscale 的故障；
- 改用 inline provider 和可见选择组后，独立代理测试恢复；
- 私有入口回退、Clash 配置回退及重新应用经过实际检查。

为了保护私人网络信息，不上传原始记录。仓库中重新参数化的 Linux 安装/回退脚本没有在所有 Linux 系统上再次执行；Windows 全机 TUN、移动端、所有软件的 UDP 兼容性都需要读者在自己的环境测试。

## 推荐验收矩阵

1. 原官方 Tailscale 开启：只用作准备阶段，不算单客户端完成。
2. 原官方 Tailscale 断开：显式本地代理 HTTP 与 UDP 测试通过。
3. 连接记录：国内测试目标 `DIRECT`，国外测试目标 `SERVER`。
4. 系统代理开启：浏览器正常，其他绕开系统代理的软件另测。
5. TUN 开启：目标应用正常，DNS、局域网及必要 UDP 流量分别检查。
6. 冷启动、切换网络、隧道短暂断连恢复：分别测试，不只看一次成功。
7. 回退：关闭 Clash 接管，原通道恢复；各服务器改动按依赖回退。

不要把 CI 绿勾、配置语法通过、设备在线、节点 `alive` 或浏览器一次能打开页面，单独当成完整验收结论。
