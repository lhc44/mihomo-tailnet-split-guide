# Tailscale 如何工作？免费流量、带宽与速度怎么算？

**先说结论：Tailscale 是设备之间的加密组网工具，不是一份附送固定流量和带宽的服务器套餐。** 速度主要取决于是否直连以及实际网络条件；服务器的流量费用仍由服务器提供商计算。

套餐信息核对日期：**2026-10-26**。以后阅读时请同时查看 [官方价格页](https://tailscale.com/pricing)，不要将本文数字当成永久承诺。

## 1. 把它理解成“介绍人 + 加密通道”

Tailscale 分为两部分：

| 部分 | 负责什么 | 是否等于网站流量都走官方服务器 |
|---|---|---|
| 控制面 | 登录设备、分发公钥和访问规则、交换连接信息 | 不是，它主要管理连接关系 |
| 数据面 | 在设备之间传输真正的数据 | 可能直连，也可能经过中继 |

两台设备加入同一个 tailnet 后，并不是把 SSH 密码交给官方服务器，而是使用各自的设备身份和密钥建立连接。数据通过 WireGuard 加密。直连和中继使用的是不同传输路径，不是不同的加密等级。[官方加密说明](https://tailscale.com/docs/concepts/tailscale-encryption)

因此，登录账号相同只是加入网络的一步，设备是否可以互访仍由 tailnet 访问规则决定。

## 2. 数据到底经过哪里？

### 路径 A：设备间直连

```text
电脑 ── 加密 UDP 连接 ── 自己的服务器
```

两边通过 NAT 穿透等方式建立直连后，实际数据不需要由官方中继转发。这通常延迟更低、吞吐更好，但仍使用普通的互联网线路，并不凭空获得一条专线。

### 路径 B：经过中继

```text
电脑 ── 加密数据 ── 中继 ── 加密数据 ── 自己的服务器
```

如果直连受到 NAT、防火墙或 UDP 限制，可以使用中继：

- **DERP**：Tailscale 运营的中继，用来协助连接并在需要时转发加密数据。
- **Peer Relay**：在自己的 tailnet 中配置另一台设备作为中继，前提是已部署并允许使用；本教程没有自动安装它。

连接初始化通常先借 DERP 交换信息并传输，再尝试升级为直连；有合适 Peer Relay 时也可能使用它。网络变化后，路径可能再次切换，所以“曾经直连过”不代表始终直连。[官方连接类型说明](https://tailscale.com/docs/reference/connection-types)

### 中继能看到网页内容吗？

DERP 转发的是设备间已经加密的数据，不能直接解密其内容。但这不等于匿名上网：控制面掌握设备及连接管理信息，而网站访问最终从自己的服务器出站。Tailscale 的设备间加密也不替代网站 HTTPS。[官方 DERP 说明](https://tailscale.com/docs/reference/derp-servers)

## 3. 免费套餐到底有多少流量？

核对时的 **Personal** 套餐价格为 `$0`，面向个人非商业用途。官方列出的主要额度是：

| 项目 | 当前价格页说明 |
|---|---|
| 用户数 | 最多 6 位用户 |
| User devices | 不限数量 |
| Tagged resources | 包含 50 个，超出有相应计费规则 |
| Ephemeral resources | 每月 1,000 分钟，用于临时资源，不是流量额度 |

这些类型不能混为一谈。例如打了 tag 的资源与普通 user device 并非同一项；老套餐账号也可能适用不同规则。以自己的 Billing 页面和 [官方价格页](https://tailscale.com/pricing) 为准。

**关于 GB/TB：当前官方价格页没有为普通 tailnet 组网列出“每月免费 100GB / 1TB”这样的固定数据包。** 不应把某个设备数、临时资源分钟数解释成可用流量，也不应把“未列月度 GB 配额”宣传成无限、无条件、满速的公共中转服务。

**1000 分钟针对临时资源，不是普通设备每月的上网倒计时。** 本教程的非临时客户端适合“服务器常驻、电脑偶尔连接”，不会因累计联网 1000 分钟而停用；设备密钥到期另按后台设置处理。见 [常见问题中的简短说明](faq.md)。

## 4. 免费套餐给多少 Mbps 带宽？

**没有一个适用于所有连接的“免费固定 100Mbps”承诺。** 需要分路径看：

| 路径 | 主要瓶颈 | 应怎样理解 |
|---|---|---|
| 直连 | 两端宽带、服务器带宽、跨网线路、CPU、延迟和丢包 | Tailscale 不会把低带宽服务器变成高带宽服务器 |
| DERP 中继 | 上述条件，加上中继路径与共享资源 | 通常更慢，还存在为公平使用而进行的吞吐限制 |
| 自建 Peer Relay | 两端到中继的线路、中继机器的带宽和性能 | 性能和成本仍由自己的基础设施决定 |

官方性能文档明确说明 DERP 会限制吞吐以保证公平使用，但没有在该文档中承诺一个人人都能获得的统一 Mbps 数字。因此别把网上一次测速当成套餐指标，也别把付费升级理解成自动购买了一条更快的中继专线。[官方性能排障](https://tailscale.com/docs/reference/troubleshooting/poor-performance-tailnet)

举例：本地宽带 300Mbps、服务器出口 20Mbps，就算成功直连，相关服务器出站仍会受到 20Mbps 这一瓶颈约束。忽略开销时 `20Mbps ÷ 8 = 2.5MB/s`，真实下载通常更低。如果走中继，还要再看中继路径的限制。

`Mbps` 是每秒多少兆比特，下载软件的 `MB/s` 是每秒多少兆字节，两者不要混淆。

## 5. 用在这份教程里，流量怎么走、谁收钱？

```text
国内目标：电脑 → 本地网络 → 网站

其他目标：电脑 → Tailscale（直连或中继）
              → 自己的服务器 → 网站
```

- 国内直连目标通常不使用服务器代理出口流量。
- 走代理的目标仍消耗本地网络流量，以及服务器套餐约定的带宽或流量。
- 使用手机热点时，传输的数据仍会消耗手机套餐流量。
- 若自建中继，还需考虑中继机器和链路本身的费用。

例如下载一个约 1GB 的文件，服务器一侧需要从网站接收数据，再把它发送给电脑，另有协议开销。云厂商究竟按出站计费、双向统计还是提供月流量包，要看其规则；不能简单统一写成“必扣 1GB”或“必扣 2GB”。

**免费组网 ≠ 免费服务器 ≠ 免费手机流量 ≠ 保证满速。**

## 6. 怎么判断自己正在直连还是中继？

对这份教程，推荐在**服务器**上查看电脑的内置节点，而不是另外启动 Windows 官方 Tailscale 来检查另一条连接：

```bash
tailscale status
# 替换为自己客户端内置节点的主机名。
tailscale ping tailnet-split-client
```

结果中：

| 看到的关键词 | 含义 |
|---|---|
| `direct` 或 ping 结果直接给出对端地址 | 当前设备间直连 |
| `relay` / `DERP(...)` | 经过 DERP |
| `peer-relay` | 经过自己的 peer relay |

首次 ping 的前几个包走 DERP、后续切为直连是正常现象。`tailscale netcheck` 可补充检查当前节点的 UDP/NAT 和中继可达性，但不是指定两台设备之间实际路径的完整结论。[官方检查方法](https://tailscale.com/docs/reference/connection-types)

要查实际带宽，应在确认连接路径后，对自己的两个端点做吞吐测试或测试实际下载。网站返回 200 只证明可达，ping 延迟低也不等于下载速度高。

## 7. 三个容易误解的点

1. **服务器公网路径受阻，不代表启用 Tailscale 就一定可达。** 可能通过中继获得另一条路径，也可能连控制面或中继都受限制。
2. **付费套餐不等于提高物理带宽。** 用户、管理功能和资源额度与实际链路性能是不同问题，采购前应核对具体承诺。
3. **Funnel 不是这里的链路。** Funnel 用来把服务发布给公网，官方另有带宽限制说明；本教程没有启用 Funnel，不应把它的规则套到所有 tailnet 连接上。[官方 Funnel 说明](https://tailscale.com/docs/features/tailscale-funnel)
